## 1. 进程模型

```
OhMyAgent.app(主进程)
 └─ SessionModel(每个会话标签一个,ChatKit)
     └─ AgentSupervisor(actor,AgentHost)
         ├─ ACPClient(actor)── ACPConnection(actor,请求表/通知分发)
         │     └─ StdioTransport ── Process: node claude-agent-acp ──stdio── JSON-RPC 2.0
         │           └─ claude CLI(Agent SDK,一个会话一个 CLI 子进程) ── MCP Servers
```

- 没有 `WorkspaceWindow` / `SessionActor` 这类类型。`SessionModel` 直接持有 `AgentSupervisor`,监督者负责拉起子进程、完成 `initialize` 握手、监测退出并发布状态(`AgentState`:idle / starting / ready / failed / exited)。
- **每个会话标签一个适配器进程**(进而各带一个 `claude` CLI),`cwd` 在 `session/new` 里传入。多文件夹工作区通过 `additionalDirectories` 传递。
- 适配器入口由 `Vendor/acp` 提供(`Scripts/stage-adapter.sh` 打包);应用包未内置时 `AdapterInstaller` 用本机 npm 安装到 `Application Support/OhMyAgent[-Dev]/acp`。
- 实测内存(见《性能优化记录》§4.1,`claude-agent-acp` 0.91.0、`claude` 2.1.303):适配器约 115 MB,1 个空闲会话合计约 383 MB(Node 约 100 MB + `claude` 约 265 MB),每多一个会话约增 245~265 MB。这就是需要休眠与驻留上限的原因。

## 2. 休眠与待命池

### 2.1 会话休眠(`SessionModel` + `SessionResidencyPolicy`)
- `SessionModel.hibernate()`:结束 Agent 进程(含终端管理器),保留时间线、草稿、标题、配置项与 `sessionId`(记为 `dormantSessionId`);有对话内容时以 `session/resume` 接回,空白会话直接丢弃进程、唤醒时新建。
- `SessionModel.wake()`:幂等,重新 `connect()`;休眠中收到需要进程的操作(发送、fork 等)会通过 `whenAwake` 先唤醒再执行;`wakeAndWait` 可等待就绪。
- `canHibernate` 条件:仅 `claudeACP` 类型会话;阶段为 ready、非运行中、非回放中;无待处理权限/提问、无排队消息;无运行中的终端、无仍在进行的工具调用、Agent 进程下无 shell 后代进程;有对话内容时必须声明 `canResume`。
- `SessionResidencyPolicy`(`WorkbenchKit`,纯函数)按 `ResidencyLimits` 选出应休眠的会话:可见会话不休眠;闲置超过 `idleSeconds` 休眠;存活数超过 `maxLive` 时按最久未用休眠。
- 默认值(`ClientPrefs`):闲置 10 分钟(`session.idleHibernateMinutes`),存活上限 `maxLiveSessions` 默认 3(范围 0~32,0 为不限)。
- 系统内存压力(`DispatchSource.makeMemoryPressureSource`,warning/critical)时限额收紧为闲置 60 秒、存活 1 个(`ResidencyLimits.underPressure`),并清空待命池;由 `WorkbenchModel.startResidencyMonitor` 定时检查并监听。

### 2.2 待命池(`EngineWarmPool`)
- 按「引擎 + 工作区」保存预先连接好的待命 `SessionModel`,切换引擎时直接取用;`capacity = 2`;失败后同一键有 300 秒冷却。
- 预热模式(`WarmMode`:关闭 / 智能 / 全部)在设置 → Agent 与模型中选择;「全部」模式下一次最多预热 `allLimit`(2)个其他引擎。

### 2.3 崩溃与断开
- `AgentSupervisor` 检测子进程退出并更新状态,UI 显示断开,可通过 `session/resume` / `session/load` 恢复。

## 3. 传输与帧格式

- Stdio,换行分隔 JSON(每行一个 JSON-RPC 消息)。stdout 只承载协议,stderr 作为日志。
- 路径一律绝对路径,行号从 1 起,字段 camelCase,判别字符串 snake_case。
- `StdioTransport` 按行读取并切分,积压指标 `backlog.acpLines`(阈值 5000 条告警);解码失败的行记日志并继续。

## 4. 握手与会话

1. `initialize`:`protocolVersion: 1`,`clientCapabilities` 含 `fs.readTextFile/writeTextFile`、`terminal`,以及调用方给出的扩展能力(如 `elicitation`)。
2. 读取 `agentCapabilities`:`loadSession`、`sessionCapabilities`(`resume` / `close` / `additionalDirectories` 等)、`mcpCapabilities`、`promptCapabilities`;可选方法先查能力再调用。
3. `session/new`(`cwd`、`mcpServers`、`additionalDirectories`)或 `session/load` / `session/resume`;fork 走 `forkSession`。
4. Agent 要求先登录(如 Antigravity)时,`SessionModel` 按其声明的认证方式调用 `authenticate` 后重试一次。
5. `session/prompt` 期间接收 `session/update`;结束时响应带 `stopReason`;`session/cancel` 用于中断。
6. 凭据:不读 Keychain,子进程继承用户登录 shell 的环境(`ShellEnvironment`),由官方 `claude` 使用自己的登录态。

## 5. session/update 到 UI

| `sessionUpdate` | UI |
| --- | --- |
| `user_message_chunk` | 回放历史的用户消息 |
| `agent_message_chunk` | 助手文本流 |
| `agent_thought_chunk` | 思维块 |
| `tool_call` / `tool_call_update` | 工具行/卡片(增量更新) |
| `plan` | Plan 卡 |
| `available_commands_update` | 斜杠命令补全表 |
| `current_mode_update` / `config_option_update` | 模式与模型/强度选择器 |
| `session_info_update` | 会话标题等 |
| `usage_update` | 用量与上下文占用 |

未知的 `sessionUpdate` 解码为 `SessionUpdate.unknown(kind:raw:)` 并保留,不会导致解码失败(前向兼容)。

## 6. 客户端方法

`ACPClientDelegate` 承接 Agent 的反向请求:`session/request_permission`(审批卡)、`fs/read_text_file` / `fs/write_text_file`、`terminal/*`(`TerminalManager`)、elicitation(表单/向导)。不同 Agent 的工具入参差异由 `ToolInputNormalizer` 统一(见《反重力ACP适配与跨引擎会话保留》)。

## 7. 并发与事件合并

- `ACPConnection` / `ACPClient` 是 actor:读循环、请求表、通知分发均在 actor 内;每个挂起请求持有 `CheckedContinuation`,连接断开时统一以错误恢复。
- 事件经 `EventCoalescer` 合批后交给主线程 `SessionModel`:基础窗口 16ms,**自适应**——窗口 ≈ 2 × 主线程处理一批的耗时(指数滑动平均),下限 16ms、上限 80ms(`AdaptiveWindow`)。批次通过 `AsyncStream` 严格按序投递;积压指标 `backlog.events`(阈值 5000 条告警)。
- `ACPClient.events` 的缓冲为 `.unbounded`,避免丢事件破坏协议。
- 主线程只应用批次;时间线只挂载最近 40 轮(`TimelineWindow`)。

## 8. 能力缺失时

- 适配器缺能力(如无 `loadSession` / `resume`)时,对应功能按能力禁用(例如会话不满足 `canResume` 则不休眠)。
- 不提供 `claude -p` 直连降级通道;适配器不可用时提示安装或指定路径(设置 → 高级)。
