# ACP 协议接入设计

> @author ygw

## 1. 进程模型

```
OhMyAgent.app(主进程)
 └─ WorkspaceWindow × N
     └─ SessionActor
         └─ ACPConnection(actor)
             └─ Process: node claude-agent-acp  ──stdio──  JSON-RPC 2.0
                 └─ claude(Agent SDK) ── MCP Servers
```

- 每个 Workspace 窗口独立一个适配器子进程,`cwd` 在 `session/new` 中传入。
- 窗口关闭:先发 `session/close`(若 Agent 声明 `sessionCapabilities.close`),再终止子进程。
- 适配器崩溃:`AgentHost` 检测退出,UI 显示"已断开",支持一键 `session/resume` 或 `session/load` 恢复。

## 2. 传输与帧格式

- Stdio,换行分隔 JSON(每行一个 JSON-RPC 消息)。stdout 仅承载协议,stderr 作为日志采集。
- ACP 约定:路径一律绝对路径,行号 1 起始,字段名 camelCase,判别字符串 snake_case。
- `ACPKit` 的读循环在后台 actor,按行切分,解码失败的行写日志并继续。
- 写入串行化,单 actor 内保证消息顺序。

## 3. 握手与会话

1. `initialize`:发送 `protocolVersion: 1`、`clientCapabilities`(声明 `fs.readTextFile`/`writeTextFile`、`terminal`、elicitation、session.compaction、session.notices 等客户端支持项)、客户端实现信息。
2. 读取 `agentCapabilities`:`loadSession`、`sessionCapabilities`(`resume`/`close`/`additionalDirectories`)、`mcpCapabilities`(`http`/`sse`)、`promptCapabilities`(图片/音频/嵌入上下文)。所有后续可选方法先检查能力再调用。
3. `authenticate`(若 `authMethods` 非空且需要)。
4. `session/new { cwd, mcpServers, additionalDirectories? }` 或 `session/load` / `session/resume`。
5. `session/prompt { sessionId, prompt: [ContentBlock] }`;期间接收 `session/update` 通知;结束时收到含 `stopReason` 的响应。
6. `session/cancel` 通知用于中断;收到 `session/request_permission` 时若轮次已取消,必须以 `cancelled` 响应。

## 4. session/update 变体到 UI 的映射

| `sessionUpdate` | UI |
| --- | --- |
| `user_message_chunk` | 回放历史时的用户消息 |
| `agent_message_chunk` | 助手文本流 |
| `agent_thought_chunk` | 思维面板 |
| `tool_call` | 新建工具卡片(`kind`、`status`、`title`、`locations`、`rawInput`) |
| `tool_call_update` | 增量更新卡片(只含变化字段) |
| `plan` | Plan 面板 |
| `available_commands_update` | 斜杠命令补全表 |
| `current_mode_update` | 模式选择器 |
| `config_option_update` | 模型/强度等选择器 |
| `session_info_update` | 会话标题等 |
| `usage_update` | 用量环与费用 |

未知的 `sessionUpdate` 一律保留为 `unknown` 并记录日志,不得导致解码失败(前向兼容)。

## 5. 客户端方法实现

| 方法 | 实现 |
| --- | --- |
| `session/request_permission` | 弹出审批面板,返回 `selected{optionId}` 或 `cancelled`;命中规则则自动应答 |
| `fs/read_text_file` / `fs/write_text_file` | 优先读取编辑器未保存缓冲区,写入走 DiffKit 记录检查点 |
| `terminal/create|output|wait_for_exit|kill|release` | 后台 PTY 管理,UI 实时展示 |
| elicitation | 渲染表单,返回结构化结果 |

## 6. 并发与背压

- `ACPConnection`:读循环、请求表、通知分发均在 actor 内。
- 通知通过 `AsyncStream<SessionEvent>` 交给 `SessionActor`;`SessionActor` 合并 8–16ms 内的文本 chunk、仅保留工具调用的最新状态,再向主线程发布"UI 快照"。
- 主线程只应用快照。快照对象为 `Sendable` 值类型。
- 请求表使用递增 id,每个挂起请求持有 `CheckedContinuation`;连接断开时统一以错误恢复。

## 7. 认证桥

- 不读取 Keychain。启动子进程时继承用户登录 shell 的环境变量(含 `PATH`、`ANTHROPIC_*`)。
- 每次窗口启动调用 `claude auth status`(通道 C)展示登录状态;`authMethods` 需要终端登录时,打开内置终端运行 `claude auth login`。

## 8. 能力降级

- 适配器缺能力(如无 `loadSession`)时,会话历史改读 `~/.claude/projects` 下的 transcript 做只读展示。
- ACP 适配器不可用时,切换 `ClaudeDirectProvider`(`claude -p --input-format stream-json --output-format stream-json`),UI 共用同一事件模型。

## 9. 测试策略

- `FakeAgent`:纯 Swift 的脚本化 ACP Agent,用于协议单测与 UI 预览。
- 集成测试:对真实 `claude-agent-acp` 完成 initialize → session/new → prompt(无工具的简单问答)。
- 模糊测试:乱序/截断/超长行/未知字段。
