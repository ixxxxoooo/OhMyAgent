## 1. 产品定位

OhMyAgent 是 macOS 专用、原生的 Cursor 风格 Agent 工作台。Swift 6 + SwiftUI + AppKit,唯一的 WebView 例外是内置浏览器标签页(`WKWebView`)。它通过 ACP(Agent Client Protocol,stdio JSON-RPC)接管本机已安装的 Claude Code,并可接入其他 ACP Agent(见 §3.6)。默认主题为「Cursor 纸感」,同时保留玻璃主题。

### 1.1 目标

1. **美观一致**:默认纸感主题;所有界面颜色、字号、圆角走设计令牌,跟随主题。
2. **高性能**:原生渲染;I/O 与解码在后台 actor;时间线只挂载最近 40 轮;性能目标见 §5。
3. **原生感**:原生菜单与快捷键、拖放、可访问性标签。
4. **功能完整**:Claude Code 的功能在 GUI 中有对应入口或明确说明,逐项状态见《ClaudeCode功能映射矩阵》。
5. **可扩展**:Agent 注册表、Bridge 工具、MCP 管理。

### 1.2 非目标

- 不复刻终端 TUI 形态(如 `/vim`、`/terminal-setup`、`/statusline`)。
- 不上 Mac App Store(沙盒会阻止拉起 `claude` 与读写 `~/.claude`);Developer ID 分发,非沙盒。
- 不做账号登录 UI,不读取、转存或代持用户的 Claude 订阅凭据(不读 Keychain)。
- 不实现 `claude -p` stream-json 直连通道:已决定不做,见《直连stream-json与共享适配器评估》。

## 3. 功能需求

### 3.1 对话与推理
- 流式文本、思维流(可折叠)、计划、子 Agent 卡片、工具调用卡片。
- 输入区:`@` 文件提及、图片、`/` 命令补全(含 Claude Code 内置命令清单与客户端斜杠命令)、运行中排队/引导。
- 协议细节见《ACP协议接入设计》(现为「协议与进程模型」)。

### 3.2 工具、权限与审查
- 权限审批:对 `session/request_permission` 弹出原生审批卡,支持自动批准规则。
- 文件修改审查:Diff 视图(双栏/行内)、检查点(`DiffKit/CheckpointStore`),每轮结束可通过「本轮改动」卡片回退到检查点。
- Elicitation 与 AskUserQuestion 向导。

### 3.3 MCP / Skills / Plugins / Subagents / Hooks / Memory
- 设置页中有对应的管理页(`SettingsPage` 的 `mcp/skills/subagents/hooks/plugins/memory`),读写由 `ClaudeConfigKit` 完成。逐项实现状态见《ClaudeCode功能映射矩阵》。

### 3.4 会话与并行
- 项目 → 会话树、会话历史、resume / fork / 重命名 / 导出 Markdown。
- 每个会话标签一个 Agent 适配器进程,带休眠与待命池(见《ACP协议接入设计》)。
- 多文件夹工作区、Git 工作树(`WorktreeManager`)与 `/worktree`、`/best-of-n` 等客户端命令。

### 3.5 设置
共 26 个设置页,清单见 §6。

### 3.6 扩展
- `AgentProvider` 协议(`AgentHost/AgentDescriptor.swift`)与 `agents.json` 注册表(`AgentRegistry`);Agent 类型为 `claudeACP` 与 `genericACP`。
- 注册表里可登记 Agent 作为 MCP 工具源(`AgentMCPEntry`)。
- Google Antigravity 一键安装与适配见《反重力ACP适配与跨引擎会话保留》。
- OhMyAgent Bridge:挂在 `LocalGateway` 上的进程内 HTTP MCP 服务(无辅助进程、非 Unix socket),工具清单以 `Sources/AgentHost/BridgeServer.swift` 的 `BridgeTool` 为准,见《ClaudeCode功能映射矩阵》§6。

### 3.7 模型来源切换(原生 ⇄ 自定义映射)
- 输入框模型下拉分两组:「Claude Code 原生(~/.claude)」与「自定义映射」;仅配置了默认槽位映射时才出现分组。
- 选择另一组的模型即切换来源:写入 `providers.json` 的 `useMapping`(全局,`ProviderSnapshot.useMapping`,缺省 true),空闲会话自动恢复(保留上下文),运行中则等本轮结束。
- 原生:不注入网关与 `ANTHROPIC_*` 覆盖,使用终端同款 `~/.claude/settings.json` 与官方登录。
- 切回原生后映射内容仍保留;也可在设置 → Claude Code 模型映射 里用「使用自定义映射」开关切换。

### 3.8 提交说明生成
- 源代码管理面板的「生成提交信息」由 `ChatKit/CommitMessageGenerator` 实现:把待提交补丁、文件清单和最近提交标题交给小模型,学习本仓库写法后输出「标题 + 可选要点正文」;没有可用模型或请求失败时退回基于补丁内容的启发式生成。请求经本机模型网关,与会话标题生成同一通道。
- 提交完成后主按钮变为「同步更改」(落后先拉取再推送);没有上游时为「发布分支」。

## 4. 鉴权需求

- 以用户环境启动官方 `claude`,由其自行使用已登录凭据。
- 客户端只负责:展示登录状态、在 Agent 要求时按其声明的认证方式调用 ACP `authenticate`、登录失效提示。
- 严禁读取 Keychain 中的 OAuth token。

## 5. 性能目标

以下均为**目标值**,不是已验收结论;预算、度量与观测方法见《性能预算与测试方案》(现为「性能预算、观测与测试方案」),实测基线与优化记录见《性能优化记录》。

| 指标 | 目标 |
| --- | --- |
| 冷启动到首帧可输入 | ≤ 300ms |
| 空载主进程内存 | 40–80MB(子进程另计) |
| 5 万行文件滚动 | 60/120Hz,hitch ratio ≤ 5ms/s |
| 流式渲染主线程单帧 | < 4ms |

## 6. 设置页清单(以 `SettingsPage` 枚举的 26 个 case 为准)

来源:`Sources/OhMyAgentApp/Settings/SettingsWindow.swift`。Claude Code 自身配置写回对应 `settings.json` 并热更新;仅属客户端的项存于 UserDefaults。侧栏分组如下。

| 分组 | 页面(case → 标题) |
| --- | --- |
| 客户端 | `general` 通用 · `appearance` 外观 · `shortcuts` 快捷键 |
| Agent | `agent` Agent 与模型 · `providers` 模型提供商 · `modelMapping` Claude Code 模型映射 · `prompts` 提示词 · `network` 网络 · `permissions` 权限 · `trust` 项目信任 · `agentExtensions` Agent 注册表 |
| 扩展(设置内可达,不在侧栏分组中) | `mcp` MCP · `skills` 技能 · `subagents` 子 Agent · `hooks` Hooks · `plugins` 插件 · `memory` 规则 |
| 工作台 | `editor` 编辑器 · `terminal` 终端 · `browser` 浏览器 · `sourceControl` 源代码管理 · `codeIntelligence` 代码智能 |
| 其他 | `usage` 用量与成本 · `privacy` 隐私与遥测 · `advanced` 高级 · `diagnostics` 诊断 |

各页内容与代码对应关系(只列可由代码核实的要点):
- 外观:主题(含自定义主题编辑器 `CustomThemeEditor`)、设置页宽度、字号等;主题规范见《UI设计规范_Cursor纸感》。
- 快捷键:动作可自定义并支持导入;默认如 ⌘N 新对话、⌘O 打开项目、⌘K 搜索、⌘B 切换项目栏、⌘⌥B 切换工具栏、⌘J 终端面板(见 `Settings/Shortcuts.swift`)。
- Agent 与模型 / 模型提供商 / 模型映射:见 §3.7 与 `ModelProvidersPage`、`ModelMappingPage`。
- 权限:权限模式与规则(`AgentPermissionPages`)。项目信任:`ClaudeConfigKit/ProjectTrust`。
- Agent 注册表:增删改 Agent、官方 Agent 一键安装(Antigravity)。
- MCP / 技能 / 子 Agent / Hooks / 插件 / 规则:对应 `MCPManagerView`、`MarkdownItemManagerView`、`HooksManagerView`、`PluginsManagerView`、`MemoryManagerView`。
- 终端:`TerminalPrefs`。源代码管理:提交署名、工作树等。代码智能:LSP 与索引忽略。
- 用量与成本:`UsagePage`(`ClaudeConfigKit/UsageScanner`、`UsageStats`)。诊断:`DiagnosticsPage`。

## 8. 验收标准(摘要)

1. 在任一项目目录完成「提问 → 思维流 → 工具调用 → 权限审批 → Diff 审查 → 回退检查点」全流程。
2. 命令映射矩阵中标注「已实现」的项可用;未实现与不适用的项有明确说明。
3. 性能指标达到 §5 目标(以《性能预算与测试方案》的度量为准)。
4. 无障碍:仅图标控件均有 `accessibilityLabel`(由 `AGENTS.md` §4 约束)。

## 9. 风险与假设

| 风险 | 应对 |
| --- | --- |
| ACP 适配器依赖 Node | 可配置路径并自动探测(`ExecutableLocator`、`Toolchain`) |
| ACP 未覆盖配置面 | 由 `ClaudeConfigKit` 直接读写配置文件,或调用 `claude` CLI(`CLIRunner`) |
| 适配器版本变化 | 前向兼容解码(未知 `sessionUpdate` 保留为 unknown) |
| 目标值未达标 | 以实测基线为准调整口径 |
| 订阅凭据合规 | 不触碰 token,由官方进程使用 |
