# 性能预算与测试方案

> @author ixxxxoooo

## 1. 预算

| 指标 | 目标 | 说明 |
| --- | --- | --- |
| 冷启动到首帧可输入 | ≤ 300ms | 主进程;适配器首帧后预热 |
| 空载主进程常驻内存 | 40–80MB | `footprint` 口径;子进程另计 |
| 5 万行文件滚动 | 60/120Hz,hitch ratio ≤ 5ms/s | Instruments Animation Hitches |
| 5 万行文件打字延迟 | P95 < 16ms | 输入到绘制 |
| 流式渲染主线程单帧 | < 4ms | signpost |
| JSON-RPC 解码吞吐 | ≥ 5 MB/s 单连接 | 后台 actor |
| 主线程阻塞 | 0 次 > 100ms | MetricKit / 内部监控 |

## 2. 设计手段

1. **启动**:`@main` 路径无同步磁盘 I/O;设置与历史异步加载;窗口先显示骨架。
2. **并发**:I/O、解码、diff、配置解析在后台 actor;主线程只应用快照。
3. **合并**:chunk 8–16ms 合并;同一工具调用多次更新只保留最新。
4. **虚拟化**:时间线 `NSCollectionView`;文件树与会话列表同样虚拟化。
5. **编辑器**:TextKit 2 视口布局;大文件模式下关闭换行与复杂高亮;高亮增量计算。
6. **缓存**:图片、diff、高亮结果设上限与 LRU。
7. **GPU**:玻璃只用于功能区;按钮组 `GlassEffectContainer`;纯色区不叠加模糊。

## 3. 度量方法

- `os_signpost`:`launch`、`firstFrame`、`promptSend`、`chunkApply`、`diffCompute`。
- `xctrace`:App Launch、Time Profiler、Animation Hitches、Allocations。
- `footprint -p <pid>` 与 `vmmap`:内存。
- XCTest `measure`:协议解码、diff、chunk 合并的基线。
- 运行时:诊断页展示主进程、适配器、claude 的 RSS 与 CPU。

## 4. 测试矩阵

| 层级 | 内容 |
| --- | --- |
| 单元 | JSON-RPC 编解码、模型前向兼容、合并器、diff、配置读写 |
| 协议 | FakeAgent 脚本化场景:流式、取消、权限、崩溃、乱序 |
| 集成 | 真实适配器握手与一次 prompt |
| UI | 快照测试(浅/深、减少透明度)、键盘导航 |
| 性能 | 上述预算对应的基线测试,超阈值失败 |
| 无障碍 | VoiceOver 巡检清单 |

## 5. 基线记录

M0 起所有 spike 的实测数据写入 `开发进度.md` 的"性能基线"章节,后续每个里程碑更新。如目标值与实测差距过大,需在文档中记录口径调整及原因。

## 6. CI 门槛

- 构建警告为 0(`-warnings-as-errors`)。
- 单元与协议测试全部通过。
- 性能基线测试回退超过 15% 失败。
