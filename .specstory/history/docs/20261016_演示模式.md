# 演示模式(Demo Mode)

> @author ygw · 2026-10-16

## 1. 为什么需要演示模式

会话流(时间线)的样式、各种工具卡、子 Agent、发送/等待/运行/冻结等状态,过去只能靠真实 Claude 触发,无法稳定复现。
演示模式把这些全部「脚本化」:不依赖真实模型与账号,一键进入,所有卡片与状态都能按需出现;同时提供一整套隔离的演示数据(多项目、历史会话、真实 Git 仓库、Claude 配置),不污染真实用户数据。

> `ScriptedAgent` 原本只是引擎原型/测试替身(关键字触发几种固定流程),不等于演示模式。现在它被抽成声明式场景引擎,演示模式在其上构建。

## 2. 怎么用

```bash
Scripts/demo.sh                      # 构建并以演示模式启动(不抢焦点)
Scripts/demo.sh --reset              # 重建演示沙盒(项目、Git 仓库、工作台状态)
Scripts/demo.sh --scenario subagents # 启动后自动运行指定场景
OMA_DEMO=1 Scripts/restart.sh        # 用 restart.sh 同样可以进入演示模式
```

| 环境变量 | 作用 |
| --- | --- |
| `OMA_DEMO=1` | 启用演示模式(强制使用 FakeAgent、隔离沙盒、窗口顶部显示「演示模式」徽标) |
| `OMA_DEMO_ROOT` | 沙盒目录,默认 `~/Library/Caches/OhMyAgent/Demo` |
| `OMA_DEMO_RESET=1` | 启动时重建沙盒 |
| `OMA_DEMO_SCENARIO=<名>` | 启动后在当前项目自动运行场景(等价于发送 `/demo-<名>`) |
| `OMA_AUTOALLOW=1` | 自动批准本轮第一个权限请求(无人值守验证用) |

运行场景的三种方式:输入框里输入 `/demo-<场景名>`(带补全)、命令面板(⇧⌘P)的「演示场景」组、提示词里写 `#demo-<场景名>`。

## 3. 场景目录

| 分组 | 场景 | 内容 |
| --- | --- | --- |
| 工具卡 | `tools-files` | 查找/读取(含超长输出)/搜索/新建/编辑/多处编辑/Notebook/删除/移动 |
| 工具卡 | `tools-shell` | ANSI 输出、超长输出、失败、多行命令、后台命令 |
| 工具卡 | `tools-web-mcp` | WebSearch、WebFetch、多个 MCP 服务器,含失败 |
| 工具卡 | `tools-plan-todo` | TodoWrite、计划条目推进、思考、模式切换 |
| 工具卡 | `terminal` | 通过客户端终端执行命令(需开启「终端」能力) |
| 交互 | `permissions` / `plan-approval` / `ask` / `changes` | 权限请求(Diff/Bash/始终允许/拒绝)、计划批准、AskUserQuestion 向导、本轮改动汇总与回退(需在界面里操作) |
| 子 Agent | `subagents` | Explore / code-reviewer / general-purpose、两层嵌套、失败 |
| 子 Agent | `subagents-parallel` / `subagents-background` | 三个并行(一失败一转后台)、后台常驻(任务坞) |
| 状态 | `states-working` / `states-frozen` | 冻结:一直思考/一直进行中,用于测试发送引导、排队、`/goal`、取消(需手动取消) |
| 状态 | `states-notices` / `states-errors` / `states-streaming` / `long-running` | 三级提示与上下文用量、各类失败、慢速长输出、约 20 秒占用 |
| 样式 | `roles` / `markdown` / `mermaid` | 角色样式同屏、Markdown 全元素与多语言代码、Mermaid 全部图种 |
| 回归 | `all` | 依次运行全部自动场景 |

覆盖守卫测试:场景必须覆盖 `ToolPresentation.Category` 全部类别、`TimelineEntry.Kind` 全部类型、各 `ToolStatus`。以后新增卡片类型而没补演示场景,测试会失败。

## 4. 演示数据

沙盒布局(`DemoPaths`):`projects/`(演示项目)、`remotes/`(本地裸远端)、`home/`(演示主目录,内含 `.claude`)、`support/`(演示版 `workbench.json`)。

| 项目 | 内容 |
| --- | --- |
| `atlas-web` | 26 个提交、4 个分支(`main`、`feature/metrics`、`fix/router-case`、`feature/ui-polish`)、合并提交、3 个标签、领先远端 1 个提交、2 个 stash;工作区含已暂存/未暂存/未跟踪/重命名/删除;多作者可 blame |
| `notes-cli` | 干净仓库(「无改动」状态) |
| `merge-lab` | 合并冲突进行中(两个冲突文件 + 一个未跟踪文件) |
| `legacy-api` | 非 Git 目录(「不是仓库」空态) |
| `empty-project` | 空目录 |

- 确定性:固定作者(林雨/陈墨/Wen Jiao)与提交时间,同样输入得到同样的提交哈希;`git` 调用使用剔除 `GIT_*` 的环境。
- 历史会话:每个项目 8~12 条(置顶、归档、长短中英标题);点开由 `session/load` 无停顿回放完整内容。
- 演示 `.claude`:记忆、3 个 Skill、3 个命令、3 个 Subagent、5 个 MCP(含项目级 1 个)、3 条 Hook、2 个插件(1 启用 1 停用)、权限规则;全部虚构,不含密钥。
- 数据版本 `DemoWorkspace.dataVersion`:改动生成内容时递增,旧沙盒自动重建。

## 5. 隔离策略

- 工作台状态写入沙盒的 `workbench.json`,不碰 `~/Library/Application Support/OhMyAgent/workbench.json`。
- `CFFIXED_USER_HOME` 与 `HOME` 重定向到沙盒 `home/`:`NSHomeDirectory()`、`homeDirectoryForCurrentUser`、Application Support(提供商/密钥)、`~/.claude`、终端与 git 子进程全部落在沙盒。
- 最近项目/会话使用独立 UserDefaults suite(`com.ohmyagent.demo`)。
- 日志仍写到真实的 `~/Library/Logs/OhMyAgent/`(`Log.bootstrap` 在重定向之前),便于排查。
- 强制使用 FakeAgent,避免误连真实 Claude;关闭系统通知与自动更新。
- 例外:外观、快捷键等纯界面偏好仍用 `UserDefaults.standard`(有意共享)。

## 6. 代码地图

- `Sources/ACPKit/ScenarioEngine.swift`、`ScriptedAgent+Engine.swift`:声明式步骤与执行端。
- `Sources/ACPKit/DemoScenarios*.swift`:场景目录;`DemoHistory.swift`、`ScriptedAgent+History.swift`:历史会话。
- `Sources/DemoKit`:沙盒、隔离层、项目与 Git 仓库生成、预置数据。
- `Sources/OhMyAgentApp/DemoLaunch.swift`、`DemoPalette.swift`:启动接入、徽标、命令面板。
- 测试:`Tests/ACPKitTests/DemoScenarioTests.swift`、`DemoHistoryTests.swift`、`Tests/ChatKitTests/DemoCoverageTests.swift`、`Tests/DemoKitTests`。

## 7. 已知限制

- 首次生成沙盒约数秒,在启动早期同步等待;之后复用。
- 交互场景需在界面里操作;冻结场景需手动取消。
- 回放的历史会话由场景数据合成,不代表真实 Claude 适配器的回放格式。
