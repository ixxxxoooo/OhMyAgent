# 演示模式自动化演示指南

> @author ygw · 2026-10-16
> 配套文档:`20261016_演示模式.md`(设计与隔离策略)。本文只回答一个问题:**怎样不碰鼠标键盘,把演示模式里的所有东西自动演示/截图/回归一遍。**

## 1. 一分钟上手

```bash
Scripts/demo.sh --reset                          # 构建 + 重建沙盒 + 以演示模式启动(不抢焦点)
Scripts/demo.sh --scenario subagents             # 启动后自动跑「多种子 Agent」场景
Scripts/demo-tour.sh                             # 无人值守导览:约 70 个画面逐个启动、截图、退出
Scripts/demo-tour.sh scenario-tools git- settings-   # 只跑名字以这些前缀开头的步骤
```

要点:

- 演示模式 = `OMA_DEMO=1`:强制使用 FakeAgent(脚本化 Agent)+ 隔离沙盒(项目、Git 仓库、`~/.claude`、工作台状态),**不会碰真实 Claude、真实账号和真实数据**。
- 一切自动化都靠环境变量(`OMA_*` 调试钩子)驱动;`Scripts/demo.sh` 会把当前 shell 里**所有 `OMA_*` 变量原样转发**给应用,所以任何钩子都能直接加在命令前:

```bash
OMA_AUTOSEND="/demo-roles" OMA_EXPAND_ALL=1 Scripts/demo.sh
```

- 不抢焦点:应用用 `open -g -n` 在后台启动;截图用 `screencapture -l<窗口号>` 只截应用窗口;**禁止用 osascript 发送按键**。

## 2. 入口与总开关

| 变量 / 参数 | 作用 |
| --- | --- |
| `OMA_DEMO=1` | 进入演示模式(`Scripts/demo.sh` 自动设置;`OMA_DEMO=1 Scripts/restart.sh` 也可) |
| `OMA_DEMO_ROOT=<目录>` | 沙盒位置,默认 `~/Library/Caches/OhMyAgent/Demo` |
| `OMA_DEMO_RESET=1` / `--reset` | 启动时重建沙盒(项目、Git 仓库、工作台状态、演示 `.claude`) |
| `OMA_DEMO_SCENARIO=<场景名>` / `--scenario <名>` | 启动后自动在当前项目运行场景,等价于 `OMA_AUTOSEND="/demo-<场景名>"` |
| `OMA_PROJECT_ROOT=<目录>` | 项目根(`demo.sh` 默认设为仓库根;演示项目由沙盒 `workbench.json` 提供) |
| `OMA_AGENT=fake` | 非演示模式下也使用 FakeAgent(演示模式下已强制) |

## 3. 调试钩子全表(自动化的“遥控器”)

所有钩子在应用启动后由 `WorkbenchView.runDebugHooks` 按下表顺序执行。路径类取值请使用**绝对路径**;沙盒里的主项目是 `$ROOT/projects/atlas-web`(`ROOT` 即 `OMA_DEMO_ROOT`)。

### 3.1 会话与输入框

| 变量 | 取值 | 效果 |
| --- | --- | --- |
| `OMA_DRAFT` | 文本 | 把文本预填进当前会话输入框(不发送;设置后应用不会激活到前台) |
| `OMA_ATTACH_IMAGE` | `路径1:路径2` | 给输入框添加图片附件;配合 `OMA_AUTOSEND` 会连同图片一起发送。沙盒内现成图片:`$ROOT/projects/atlas-web/assets/logo.png` |
| `OMA_AUTOSEND` | 文本 | 等会话就绪后自动发送(可以是 `/demo-<场景>`、`#demo-<场景>` 或任意文字) |
| `OMA_AUTOALLOW` | 任意 | 自动批准**第一个**权限请求(之后的请求仍停在等待态,可用来截「第二个权限卡」) |
| `OMA_EXPAND_ALL` | 任意 | 所有工具卡与分组默认展开(截图看细节用) |
| `OMA_OPEN_SUBAGENT` | 工具调用 ID | 等该子 Agent 条目出现后以标签打开其只读会话。演示场景里的 ID 会带运行序号后缀,**首次运行为 `-r1`**,如 `a_explore-r1` |
| `OMA_USAGE_PANEL` | 任意 | 启动即展开「上下文用量」面板(配合 `states-notices` 场景) |
| `OMA_BRANCH_MENU` | 任意 | 启动即展开分支切换弹层 |

### 3.2 面板、标签与编辑器

| 变量 | 取值 | 效果 |
| --- | --- | --- |
| `OMA_RIGHT_PANE` | `changes` `plan` `outline` `problems` `files` `search` `git` `terminal` | 打开右侧栏对应面板 |
| `OMA_SEARCH_QUERY` | 文本 | 配合 `OMA_RIGHT_PANE=search` 预填搜索词 |
| `OMA_SHOW_RIGHT` / `OMA_SHOW_BOTTOM` | 任意 | 强制显示右侧栏 / 底部面板 |
| `OMA_BOTTOM_PANE` | `terminal` `output` `problems` | 选择底部面板页 |
| `OMA_PALETTE` | `commands` / `files` | 打开命令面板 / 快速打开;`OMA_PALETTE_QUERY` 预填查询 |
| `OMA_OPEN_FILE` | 绝对路径 | 以固定标签打开文件;`OMA_OPEN_LINE` 指定行;`OMA_SPLIT=right\|bottom` 把它分屏到会话组边缘 |
| `OMA_EDIT_APPEND` / `OMA_EDIT_SAVE=1` | 文本 / 1 | 配合 `OMA_OPEN_FILE`:追加文本验证「未保存」标记,再保存 |
| `OMA_OPEN_DIFF` | 绝对路径 | 打开该文件的 Diff 标签 |
| `OMA_OPEN_HISTORY` | `1` 或文件绝对路径 | 打开整个仓库 / 单文件的 Git 历史 |
| `OMA_OPEN_BLAME` | 绝对路径 | 打开逐行追溯(blame) |
| `OMA_OPEN_TERMINAL` | 任意 | 打开终端标签;`OMA_TERM_INPUT` 在 shell 就绪后输入(`\n` 表示回车) |
| `OMA_OPEN_MERMAID` | 源码(`\n` 表示换行) | 以预览标签打开 Mermaid 图 |
| `OMA_OPEN_PROJECTS` | 路径,冒号分隔 | 覆盖启动时恢复的项目列表(用来单独演示 `merge-lab`、`legacy-api` 等) |

### 3.3 设置

| 变量 | 取值 | 效果 |
| --- | --- | --- |
| `OMA_OPEN_SETTINGS` | 任意 | 启动即打开设置 |
| `OMA_SETTINGS_PAGE` | `general` `appearance` `shortcuts` `agent` `providers` `prompts` `network` `permissions` `trust` `agentExtensions` `mcp` `skills` `subagents` `hooks` `plugins` `memory` `editor` `terminal` `usage` `privacy` `advanced` `diagnostics` | 打开的设置页 |
| `OMA_SECTION` | `mcp` `skills` `agents` `hooks` `plugins` `memory` | 旧参数:映射为对应的独立设置页(兼容) |
| `OMA_HUB` / `OMA_HUB_QUERY` | `all` `sessions` `projects` `files` `actions` `settings` / 任意文本 | 打开中央搜索窗并预填查询 |

### 3.4 其他

`OMA_LSP_PROBE=行:列`(把 hover/定义/补全结果写入日志)、`OMA_PERF_OUT`(首帧耗时输出文件)、`OMA_LOG_LEVEL`、`OMA_LOG_TRAFFIC`(日志相关,见 `Scripts/logs.sh`)。

## 4. 场景目录与自动化方式

运行场景的方式:输入框 `/demo-<名>`(带补全)、命令面板「演示场景」、提示词写 `#demo-<名>`,以及上面的 `OMA_DEMO_SCENARIO` / `OMA_AUTOSEND`。

「运行方式」含义:**自动** = 自己跑到结束;**冻结** = 故意停在进行中,取消后才结束;**交互** = 中途要点按钮。

| 场景 | 运行方式 | 内容 | 无人值守怎么演示 |
| --- | --- | --- | --- |
| `tools-files` | 自动 | 查找/读取/搜索/新建/编辑/多处编辑/Notebook/删除/移动 | `OMA_DEMO_SCENARIO=tools-files OMA_EXPAND_ALL=1` |
| `tools-shell` | 自动 | ANSI、超长输出、失败、多行、后台命令 | 同上 |
| `tools-web-mcp` | 自动 | WebSearch/WebFetch/多个 MCP(含失败) | 同上 |
| `tools-plan-todo` | 自动 | TodoWrite、计划推进、思考、模式切换 | 同上 |
| `terminal` | 自动 | 通过客户端终端执行命令 | 同上 |
| `subagents` | 自动 | 三类子 Agent、两层嵌套、失败 | 加 `OMA_OPEN_SUBAGENT=a_explore-r1` 可顺便打开其标签 |
| `subagents-parallel` | 自动 | 三个并行,一个失败、一个转后台 | 同上 |
| `subagents-background` | 自动 | 后台常驻(任务坞) | 同上 |
| `states-notices` | 自动 | info/warning/error 提示与上下文用量 | 加 `OMA_USAGE_PANEL=1` 展开用量面板 |
| `states-errors` | 自动 | 失败的工具/子 Agent/错误提示 | `OMA_EXPAND_ALL=1` |
| `states-streaming` | 自动 | 慢速长输出(滚动跟随、渲染性能) | 等待约 10 秒后截图 |
| `long-running` | 自动 | 约 20 秒占用,任务坞三个分区有数据 | 等待约 14 秒后截图 |
| `roles` / `markdown` / `mermaid` | 自动 | 角色样式、Markdown 全元素、Mermaid 全图种 | 直接截图 |
| `states-working` | 冻结 | 一直思考,测试引导/排队/`/goal`/取消 | 截冻结画面;取消需手动点停止 |
| `states-frozen` | 冻结 | 待处理/进行中的工具与子 Agent 停在原地 | 截冻结画面 |
| `permissions` | 交互 | Diff 权限、Bash 权限、始终允许、拒绝 | `OMA_AUTOALLOW=1` 自动批准第一个,第二个停在等待态 |
| `plan-approval` | 交互 | 计划批准卡 | 只能截等待态,批准需手动点击 |
| `ask` | 交互 | AskUserQuestion 逐题向导 | 只能截第一题,回答需手动点击 |
| `changes` | 交互 | 真实改文件,生成「改动」汇总与回退 | 只能截汇总前后,回退需手动点击 |
| `all` | 自动 | 依次运行全部自动场景 | 等待约 60 秒;适合性能/稳定性回归 |
| `legacy-sub` `legacy-sub2` `legacy-showcase` `legacy-mermaid` | 自动 | 旧关键字 `#sub` `#sub2` `#showcase` `#mermaid` 的等价场景 | 兼容旧测试用 |

> 交互/冻结场景的“要点按钮”部分无法在不使用 osascript 的前提下自动化,这是有意的约束(避免抢焦点、乱发按键)。覆盖它们的逻辑正确性靠 `Tests/ACPKitTests/DemoScenarioTests.swift` 里的自动化测试。

## 5. 无人值守导览脚本 `Scripts/demo-tour.sh`

```bash
Scripts/demo-tour.sh --list                       # 列出全部步骤名(约 70 个)
Scripts/demo-tour.sh                              # 全跑一遍(约 20 分钟),截图落在 /tmp/oma-demo-tour
Scripts/demo-tour.sh --out ~/Desktop/tour --reset # 指定输出目录并先重建沙盒
Scripts/demo-tour.sh --wait 2 scenario-           # 机器较慢:等待时间 ×2,只跑场景步骤
Scripts/demo-tour.sh --no-build git- settings-    # 不重新构建,只跑 Git 与设置相关步骤
```

每一步做的事:结束旧进程 → 删除沙盒里的 `workbench.json`(下次启动由 `DemoSeed` 重新预置,保证每步从干净的工作台状态开始,不会恢复上一步的标签页)→ `open -g -n` 以该步骤的环境变量启动 → 等待 → 对**面积最大的可见应用窗口**截图 → 结束进程。

步骤分组(名称即文件名,`<步骤>.png`):

| 前缀 | 内容 |
| --- | --- |
| `scenario-*` | 全部演示场景(含冻结、交互、`permissions-autoallow`、`all`) |
| `chat-*` | 折叠态工具卡、用量面板、子 Agent 标签、图片发送与预填、分支弹层、命令面板/快速打开 |
| `git-*` | Git 面板、改动面板、文件树、搜索、Diff、整库/单文件历史、blame、合并冲突/干净仓库/非仓库/空项目 |
| `editor-*` / `terminal-tab` / `bottom-panel` | 文件、右侧分屏、Mermaid 预览、终端、底部面板 |
| `settings-*` | 17 个设置页与「工具与扩展」6 个分区 |

新增步骤:在脚本的步骤表里加一行 `add "名称" 等待秒数 "KEY=VALUE;KEY=VALUE"`(值里可含空格,不能含 `;` 与 `|`)。

截图保留在输出目录,**看完请自行删除**(仓库不应提交截图)。

## 6. 手动拼装一个自定义演示

不想用导览脚本时,三步即可:

```bash
# 1) 启动(所有 OMA_* 都会转发)
OMA_DEMO_ROOT=/tmp/oma-demo OMA_ATTACH_IMAGE=/tmp/oma-demo/projects/atlas-web/assets/logo.png \
OMA_AUTOSEND="看看这张图 /demo-roles" OMA_EXPAND_ALL=1 Scripts/demo.sh --reset

# 2) 等待几秒后,按窗口号截图(不抢焦点)
python3 - <<'PY'
import subprocess, Quartz
best, area = None, 0
for w in Quartz.CGWindowListCopyWindowInfo(Quartz.kCGWindowListOptionAll, Quartz.kCGNullWindowID):
    b = w["kCGWindowBounds"]
    if w.get("kCGWindowOwnerName") == "OhMyAgent" and w.get("kCGWindowLayer") == 0 and b["Width"] > 400 and b["Height"] > 300 and b["Width"] * b["Height"] > area:
        best, area = w["kCGWindowNumber"], b["Width"] * b["Height"]
subprocess.run(["screencapture", "-x", "-o", "-l%d" % best, "/tmp/demo.png"])
PY

# 3) 看完删除截图并退出
rm -f /tmp/demo.png; pkill -x OhMyAgent; pkill -x FakeAgent
```

> 注意:全屏透明的覆盖层窗口也属于 OhMyAgent,所以按“面积最大且有名字的窗口”挑,而不是取第一个。

## 7. 演示数据速查(要演示什么就打开哪里)

| 想演示 | 项目 | 怎么打开 |
| --- | --- | --- |
| 多分支/标签/stash/领先远端/多种工作区改动/blame | `atlas-web`(默认) | `OMA_RIGHT_PANE=git`、`OMA_OPEN_DIFF=$ROOT/projects/atlas-web/Sources/AtlasCore/Cache.swift`、`OMA_OPEN_BLAME=…/Router.swift` |
| 「无改动」干净仓库 | `notes-cli` | `OMA_OPEN_PROJECTS=$ROOT/projects/notes-cli` |

| 「不是仓库」空态 | `legacy-api` | `OMA_OPEN_PROJECTS=$ROOT/projects/legacy-api` |

| 项目 → 会话树、置顶/归档/长短标题、历史会话回放 | 5 个项目各 8~12 条 | 侧栏点击;或界面里打开历史会话(由 `session/load` 无停顿回放) |

## 8. 如何做回归验收

1. `Scripts/ci.sh`:零警告构建 + 全部测试(其中 `DemoCoverageTests` 守卫:新增工具卡类别/时间线条目类型/工具状态而没补演示场景,会失败)。
2. `Scripts/demo-tour.sh --reset`:全量画面导览,逐张浏览截图;日志在 `~/Library/Logs/OhMyAgent/`(`Scripts/logs.sh`)。
3. `OMA_DEMO_SCENARIO=all`:跑全量串联场景,观察是否卡顿/崩溃(`Scripts/perf.sh` 为独立的性能门槛)。

## 9. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 截图是空白/只有透明层 | 取到了覆盖层窗口:按面积最大且有窗口名挑选(导览脚本已处理) |
| 截图里有上一次的标签页 | 工作台状态被恢复:删除 `$ROOT/support/workbench.json`(导览脚本每步自动做),或加 `--reset` |
| `OMA_OPEN_SUBAGENT` 打开后显示「子任务已不可用」 | 工具调用 ID 写错;演示场景 ID 带 `-r<运行序号>` 后缀,首次运行用 `-r1` |
| 首次启动很慢 | 首次要生成沙盒(项目与 Git 仓库,数秒),之后复用;导览脚本对第一步额外等待 25 秒 |
| 没有 `OMA_*` 生效 | 不要用 `Scripts/demo.sh` 以外的方式再套一层 `env -i`;`open` 需要 `--env`,`demo.sh` 已处理 |
| 想看真实 Claude | 不要设置 `OMA_DEMO`;演示模式永远使用 FakeAgent |

## 10. 已知限制

- 只有“显示”类操作可无人值守;**点击类**(批准权限、回答问题、取消冻结场景、回退改动)必须手动。
- 回放的历史会话由场景数据合成,不代表真实 Claude 适配器的回放格式。
- 外观/快捷键等界面偏好仍使用 `UserDefaults.standard`,与真实应用共享(有意为之)。
