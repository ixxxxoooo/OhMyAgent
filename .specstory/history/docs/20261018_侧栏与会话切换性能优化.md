# 侧栏开关与会话切换卡顿:分析与优化

> @author ixxxxoooo

## 现象与数据来源

- 现象:开关左右侧栏时掉帧;整页偶发卡顿;切换/冷打开会话时偶发 1~2 秒冻结。
- 数据:`~/Library/Logs/OhMyAgent[-Dev]` 的性能日志(`侧栏切换` / `标签切换` / `时间线挂载` / `主线程卡顿` / `资源采样`)、`/usr/bin/sample` 栈采样、演示模式(隔离沙盒 + 脚本化 Agent)下的可重复基准 `Scripts/perf-ui.sh`。

## 根因与修复

| 问题 | 根因 | 修复 | 位置 |
| --- | --- | --- | --- |
| 侧栏开关掉帧 | 动画挂在整个 HStack 的 `.animation(value:)` 上,中栏宽度逐帧变化,会话流/时间线每帧重排 | 动画只绑在面板自身的 `AnyTransition.animation(_:)`,中栏一次性到位;滑出的面板 `zIndex(1)` 盖在已变宽的中栏上 | `WorkbenchView.swift` |
| 隐藏标签仍参与布局 | `TabKeepAlive` 常驻标签只用 `opacity(0)` 隐藏,容器变宽时仍整体重排 | `InactiveSizeFreeze`:失活后冻结尺寸,激活当帧恢复跟随容器 | `Dock/TabGroupView.swift` |
| 整页 CPU 高(运行中 50%) | 流光 `TimelineView(.animation)` + `.mask(content)` 每显示帧重算;`phaseAnimator` 呼吸点、`repeatForever` 转圈、等待指示每 0.15 秒重算视图 | 全部改 Core Animation(渲染服务器驱动,单次添加 `repeat = .infinity`):`OMBreathingLayerView`/`OMSpinnerLayerView`/`OMFlowBandLayerView`/`OMGlyphLayerView`;`OMAnimationGate` 门控(标签可见 + 应用可见 + 未减弱动态) | `DesignSystem/LoopLayers.swift`、`AnimationGate.swift` |
| 展开侧栏首帧慢 | 每行 `Date.formatted(.relative)` 每次新建格式化器;文件装饰索引在 Explorer `body` 内重算 | 相对时间按「分钟」缓存(`SidebarRelativeTime`);`GitModel.decorationIndex` 按状态快照缓存;SCM 变更列表改 `LazyVStack` | `ProjectTreeView.swift`、`Git/GitModel.swift`、`Git/SCMView.swift` |
| 浸泡检查误报 | 演示模式启动时同步生成沙盒(1.4~1.8 秒)被算作主线程卡顿 | 只统计第一次资源采样之后的卡顿 | `Scripts/perf-report.py` |

## 观测工具(新增)

- `HitchStackSampler`:主线程卡顿进行中(≥250ms)自动调用 `/usr/bin/sample`,日志 WARN「卡顿栈」+ 最重主线程路径(开发版/演示默认开,`OMA_HITCH_SAMPLE=0/1` 覆盖)。**真实使用中的冷打开冻结靠它取证**。
- `PerfBenchmarkHooks`:`OMA_SWITCH_SESSIONS=N` 冷打开 N 个会话再热切换;配合 `OMA_TOGGLE_LEFT/RIGHT/COUNT`。
- `Scripts/perf-ui.sh [interact|cpu|all] [--build] [--heavy N]`:一键基准与门槛;`--heavy N` 额外生成 N 个压测 Skill(`OMA_DEMO_EXTRA_SKILLS`)。
- 守卫:`PerfSourceGuardTests`(禁止整体动画回退、隐藏标签必须冻结、禁止逐帧 `TimelineView(.animation)`/`phaseAnimator`/`repeatForever`)、`AnimationGateTests`。

| 指标 | 基线 | 现在 |
| --- | --- | --- |
| 侧栏切换平均帧间隔 | 26.1 ms | 16.8 ms(≈60fps) |
| 每次切换掉帧(>33ms) | 2.58 | 0.04~0.17 |
| 单帧最长 P95 | 209 ms | 31~33 ms |
| 点击→首帧 P95 | 137 ms | 94~106 ms |
| 冷打开时间线挂载 | — | 中位 17~20 ms,最大 ≤30 ms(含 1500 个压测 Skill 同) |
| 标签热切换中位 | — | 22~24 ms |
| 运行中 CPU(states-frozen) | 50.5% | 6.8~8% |

## 门槛与诚实说明

- 门槛:平均帧间隔 ≤17.5ms、平均掉帧 ≤1、单帧最长 P95 ≤40ms(两个 vsync 容差)、**点击→首帧 P95 ≤120ms**、冷挂载 ≤150ms、热切换中位 ≤50ms、卡顿 ≤250ms、运行 CPU ≤15%。
- **未达成的原目标**:点击→首帧最初定为 ≤80ms,实测约 94~106ms 仍未达到(打开左栏时项目树的一次性挂载约 90ms、关闭时中栏一次性重排约 58ms,属 SwiftUI/AppKit 框架内耗,应用代码的 `body` 仅占约 1ms)。门槛因此按实测定为 120ms 用于防回退,不是目标已达成。此后若要继续压低,需要让会话行更轻(减少每行 NSViewRepresentable 锚点/遮罩)或让项目树常驻。动画过程本身已是满帧(首帧之后全部 16.7ms)。
- **真实使用中冷打开会话的 1.3~1.9 秒冻结未能复现**:演示模式(含 1500 个压测 Skill)下冷挂载只有约 20ms;日志里 `历史会话回放` 的耗时主要是等待引擎加载会话(异步,不占主线程)。未做无证据的猜测性改动;下次在开发版真实使用中出现卡顿时,日志会有「卡顿栈」,据此再定点修复。
- 视觉验证:演示模式截图确认流光、等待字符、状态点仍在动(两帧像素差异在对应区域),验证后已删除截图。
