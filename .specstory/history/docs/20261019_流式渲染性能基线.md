# 流式渲染性能基线与优化记录

> @author ixxxxoooo
> 日期:2026-10-19
> 背景:与 `~/baocode`(Flutter)对比后,判断 OhMyAgent 的卡顿集中在**流式回复时主线程的文字排版**、滚动跟随的高频回调与遮罩离屏渲染。本文记录基线与每项优化前后的数据。

## 1. 度量方法

- **流式渲染微基准**:`Tests/OhMyAgentAppTests/StreamingRenderBenchTests.swift`。把一条约 20KB 的助手回复(标题、段落、列表、行内代码、引用交替,无围栏代码块,即一整段文字)按 48 字一批追加,每批执行「Markdown 增量解析 → 文字段渲染 → 排版测量」,统计每批主线程耗时。运行:`Scripts/test.sh --filter StreamingRenderBench`,结果在标准错误的 `[基准]` 行。数据为 **debug 构建**,绝对值偏大,但相对变化有效(耗时主要在 TextKit / AttributedString 等系统代码里)。
- **UI 交互基准**:`Scripts/perf-ui.sh interact --build --sessions 6`(演示模式,release 构建)。
- 卡顿取证:`OMA_HITCH_SAMPLE=1`(`HitchStackSampler`,日志「卡顿栈」)。

## 2. 基线(优化前)

| 项 | 数据 |
|---|---|
| 20KB 流式,全程每批 | 216 批,中位 13.6ms,P95 26.7ms,最大 42.7ms,合计 3051ms |
| 20KB 流式,最后 25% | 中位 24.5ms,P95 27.6ms(已超过一帧 16.7ms) |
| UI:冷打开时间线挂载 | 41ms |
| UI:标签热切换 | 中位 24ms,P95 87ms |
| UI:启动前主线程卡顿 | 5 次,最长 260ms |

**结论**:每批耗时随文本长度**线性增长**(前 75% 约 8ms → 后 25% 约 24ms),说明每批都对整段文字重建富文本并整体重排。这与代码阅读的判断一致(`MarkdownTextRunBuilder.build` 整段重建 + `setAttributedString` + `ensureLayout`)。
