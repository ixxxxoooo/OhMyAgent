## 1. 根因与条目(A~K)

| 条目 | 现象 | 做法 | 主要文件 |
| --- | --- | --- | --- |
| A | 拖窗口每帧让全局失效 | `onGeometryChange` 返回宽度**档位**(`CompactLayout.Bucket`),仅档位变化才写 layout | `WorkbenchView`、`CompactLayout` |
| B | 拖分栏每 tick 写 `layout` 结构体 | `PanelDragState`:拖动中只写临时尺寸,松手 `commitPanelDrag`;`DockView` 比例暂存 `@State`;`dock.didSet` 仅比例变化时跳过会话回收 | `PanelDragState`、`PanelResizer`、`BottomPanelView`、`TerminalPanelView`、`DockView`、`DockLayout.differsOnlyInRatios` |
| K | 拖拽范围、滚动条策略、落盘拖慢主线程 | `workspaceFrame` 不参与观察;`ScrollbarPolicy` 锚点未变不重挂;`saveNow` 的 JSON 编码与写盘移到后台,`SaveSequencer` 代号保证新快照不被旧快照覆盖 | `TerminalPlacementViews`、`ScrollbarPolicy`、`SaveSequencer` |
| C | 窗口/分栏拖动时终端反复重排 | `LiveResizeGate`:实时缩放 / 拖动期间终端保持原列数只裁剪,结束或停稳(~100ms)后一次性重排 | `Terminal/LiveResizeGate`、`OMTerminalView` |
| D | 滚动让 `ChatView` 整体重算 | `FollowTracker`(暂存字段 `@ObservationIgnored`,只在 `pinned/unseen/hasActivity` 真变化时发布) | `FollowTracker` |
| E | 时间线 revision / 锚点轨道 / 渐隐牵连整个视图 | `TimelineRevisionDriver`、`AnchorJumpAction`(稳定引用)与渐隐叶子化 | `TimelineChatLeaves`、`ConversationAnchorRail` |
| F | 吸顶用户消息每帧写字典 | `userMinY` 不观察,只发布取整 `pushOffset` 与 `targetID`;`EntryIndexTable` 替代线性扫描 | `StickyUserViews` |
| G | Markdown 文字段每次 `updateNSView` 重设属性、反复测量 | `AppearanceSignature` 未变不重设;尺寸按(宽度,内容修订)缓存,退化提议不改容器宽度 | `MarkdownTextRun` |
| H | `OMColors.*` 每次读取都现算/新建动态色 | `ResolvedTokens`:主题变化(`ThemeRuntime.generation`)时一次性重建 | `DesignSystem/ResolvedTokens` |
| I | 侧栏每次 body 重算排序/解析日期/查磁盘;渐隐 `.mask` 离屏渲染 | `DateParseCache`(有界、加锁)记忆化 ISO8601;`RecentStore.projects()` 5 秒 TTL 缓存;`pinned` 只遍历有置顶的项目;`sidebarSessions` 用 `Set` 查已打开会话、无打开会话时不建字典;会话行与标签标题的渐隐改为背景色渐变覆盖层 `omFadeTrailingEdge` | `DateParseCache`、`AttentionCenter`、`ProjectTreeView`、`TabBarView`、`FadeTrailingEdge` |
| J | 行级小毛病 | 悬停状态下沉到 `HoverStateReader` 叶子(工具行 / 浏览分组 / 回合折叠行 / 用户气泡);终端复制按需取纯文本、ANSI 渲染单项缓存、`onChange` 比较长度;`SubagentStatus.lastLine` 从尾部找换行;行内 Markdown 按原文缓存(`InlineMarkdownCache`);`CollapsibleUserText` 仅「溢出且收起」才挂 mask、折叠阈值滞回;用户气泡改 `omSolidChrome`(不透明铬面,**纸感主题外观与原先玻璃回退完全一致,仅玻璃主题由半透明变不透明**) | `ToolRowViews`、`TimelineEntryViews`、`ANSITextView`、`SubagentStatus`、`InlineMarkdownCache`、`CollapsibleUserText`、`GlassModifiers` |
| 其它 | 右键菜单锚点登记 O(n);`omTooltip` 每次 body 查本地化 | `WeakRegistry`(保序弱引用表,O(1) 登记);提示文字本地化推迟到悬停,无障碍提示用 `LocalizedStringResource` 渲染时解析 | `Menu/WeakRegistry`、`Tooltip` |

## 2. 基准方法

钩子(`ResizeBenchmarkHooks`,仅脚本化验证用;复用 `PanelToggleProbe` 的 body 计数):

| 环境变量 | 作用 | 日志名 |
| --- | --- | --- |
| `OMA_RESIZE_SWEEP=N` | 主窗口宽度 1400↔900 逐帧 `setFrame`,往返 N 次 | `缩放基准` |
| `OMA_DRAG_SWEEP=sidebar\|tools\|bottom\|dock` | 按 `PanelResizer` 同一写入路径逐帧改尺寸(dock 为逐帧提交比例,代表最坏情况) | `拖分栏基准` |
| `OMA_SCROLL_SWEEP=N` | 会话流 `NSScrollView` 逐帧上下滚动 N 个来回(演示场景默认 `markdown-edge`,可用 `SCENARIO_LONG` 覆盖) | `滚动基准` |

`Scripts/perf-ui.sh resize|drag|scroll|stream [--sweeps N]`,`perf-report.py ui --sweep-only` 汇总(只记录,**暂不设门槛**)。采样驱动自身有 `Task.sleep(16ms)` 抖动,绝对值偏保守,同一方法对比前后才有意义;单次结果有 ±数帧的波动。

## 3. 前后数据(release 演示模式,Apple Silicon,同一台机器背靠背)

基线 = 优化前提交 `a2ac937` + 同一套基准钩子(拖分栏沿用旧写法逐帧直写 `layout`);优化后 = 当前 `main`。

| 场景 | 指标 | 优化前 | 优化后 |
| --- | --- | --- | --- |
| 窗口缩放(3 个来回) | 平均帧间隔 / 掉帧(>33ms) / 单帧最长 | 25.1ms / 30 / 75.8ms | 17.6~20.3ms / 4~14 / 39~53ms |
| 拖项目栏 | 平均 / 掉帧 / 最长 | 19.4ms / 22 / 49.2ms | 16.7~17.8ms / 0~11 / 17~33ms |
| 拖项目栏 | 视图 body 重算(180 个 tick) | `center`=180、`tabGroup`=180 | 0~1 |
| 拖工具栏 | 平均 / 掉帧 / 最长 | 19.0ms / 20 / 58.4ms | 17.9ms / 12 / 40.6ms |
| 拖工具栏 | 视图 body 重算 | `center`=180、`rightPane`=180、`tabGroup`=180 | 各 ≤1 |
| 拖底栏 | 平均 / 掉帧 / 最长 | 18.2ms / 9 / 81.8ms | 17.0ms / 2 / 44.4ms |
| 编辑区分屏比例(逐帧提交) | 平均 / 掉帧 / 最长 | 17.0ms / 2 / 50.8ms | 17.7ms / 6 / 51.3ms(持平,噪声内) |
| 会话流滚动(3 个来回) | 平均 / 掉帧 / 最长 | **57.3ms / 100 / 307ms** | **16.8ms / 2 / 33ms** |

说明:
- 拖分栏的 body 重算次数从每 tick 一次降到几乎为 0,是 B 的直接证据;帧间隔的剩余差异受基准驱动抖动影响。
- 滚动是收益最大的一项(D/E/F/G/H 叠加)。
- 编辑区分屏的基准路径是「逐帧提交比例」(最坏情况),与线上 `DockView` 的「拖动中暂存、松手提交」不同,因此基准里看不出差别;线上路径由 `PerfSourceGuardTests` 守卫。
- 流式输出的单批渲染耗时仍以 `20261019_流式渲染性能基线.md` 为准(`StreamingRenderBenchTests` 复测不回退)。
