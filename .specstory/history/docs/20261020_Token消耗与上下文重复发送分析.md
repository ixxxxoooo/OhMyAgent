# Token 消耗与「是否重复发送上下文」分析(实测)

> @author ixxxxoooo · 2026-10-20 · 对应问题:「每次发消息是不是有重复发送上下文的嫌疑?token 消耗太快」

## 结论(先看这里)

1. **OhMyAgent 没有重复发送上下文。** 客户端到 Agent 之间(ACP `session/prompt`)每轮只发新消息;上下文由 Claude Code(或 OpenCode)进程自己持有。
2. **大模型 API 本身是无状态的**:Claude Code 每轮调用上游模型时都会把「系统提示 + 工具定义 + 全部历史」整包再发一次,这是协议决定的,任何客户端都一样。真正决定费用的是**提示缓存**:命中缓存的部分按约 10% 计价。
3. 实测(真实 Claude Code,`claude -p … --resume` 连续 6 轮,单轮只问一句 `n+n`):

| 轮次 | 新输入 | 缓存写入 | 缓存读取 | 输出 |
|---|---|---|---|---|
| 1 | 2 | 14094 | 8858 | 295 |
| 2 | 2 | 640 | 22952 | 44 |
| 3 | 2 | 389 | 23592 | 11 |
| 4 | 2 | 356 | 23981 | 11 |
| 5 | 2 | 356 | 24337 | 11 |
| 6 | 2 | 356 | 24693 | 111 |

   - 第 1 轮把约 2.2 万 token 的**基础前缀**(Claude Code 系统提示 + 内置工具定义)写入缓存;
   - 之后每轮只**新增写入 ~350 token**(本轮的问答),其余 ~2.4 万全部是**缓存读取**(10% 价)。
   - 也就是说「重复发送」的是已缓存的前缀,**不是**每轮按全价重算。
4. 如果感觉 token 涨得快,主要原因有三:
   - **基础前缀本身就有 ~2.2 万 token**(与项目、MCP 数量相关;装的 MCP 越多越大);
   - **长会话里每轮读缓存的量随历史线性增长**(虽然便宜,但 token 总数会很大;界面若把缓存读取也累计进「消耗」会显得很吓人);
   - **缓存会过期**:Claude Code 默认缓存 5 分钟/1 小时(`ephemeral_5m`/`1h`),停顿太久再发,整段历史会重新「缓存写入」(1.25× 价)。

## 每条消息触发了几次上游请求(假网关实测,不耗 token)

`Scripts/token-probe.py --turns 6`:用本地假网关(`Scripts/mock-anthropic.py --log`)接住真实的 `claude-agent-acp` + `claude`,统计每轮的上游请求:

| 轮次 | 上游请求数 | 主请求体(KB) | 消息条数 | system(KB) | tools(个/KB) | 缓存断点 |
|---|---|---|---|---|---|---|
| 1 | 3 | 64.5 | 2 | 6.7 | 12/29.0 | 3 |
| 2 | 3 | 65.5 | 5 | 6.7 | 12/29.0 | 4 |
| 3 | 3 | 65.8 | 8 | 6.7 | 12/29.0 | 4 |
| 4 | 3 | 66.1 | 11 | 6.7 | 12/29.0 | 4 |
| 5 | 3 | 66.4 | 14 | 6.7 | 12/29.0 | 4 |
| 6 | 3 | 66.7 | 17 | 6.7 | 12/29.0 | 4 |

- 每轮 **1 个主请求**(带工具与全部历史,**带 4 个 `cache_control` 缓存断点**——说明缓存机制在正常工作)+ **2 个很小的后台请求**(各约 4KB、无工具:Claude Code 自己的会话标题/话题摘要,走「小模型」槽位)。
- 主请求体增长缓慢(每轮 +0.3KB),印证历史是**增量**累积,没有被重复叠加。
- 后台小请求:在 OhMyAgent 里它们会走「小模型」槽位映射,费用可忽略;若想完全关闭,可在「设置 → 隐私/高级」打开 `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`。

## 与 baocode 对照的最佳实践

| 实践 | 现状 |
|---|---|
| 稳定前缀 + 缓存断点 | Claude Code 已自带 4 个断点;OhMyAgent 不改写 system/tools,不破坏前缀 |
| 只发增量 | ACP `session/prompt` 只发新消息;已实测 |
| 请求体确定性序列化 | 代理做 OpenAI 转换时使用 `.sortedKeys`,工具顺序保持,前缀稳定 |
| 缓存路由键 | 本次新增:OpenAI 官方端点带 `prompt_cache_key`(按路由+模型稳定),其他端点不写入(避免严格网关拒收未知字段) |
| 缓存命中回读 | 代理把 `cached_tokens` 折算为 `cache_read_input_tokens`,界面「提示缓存」统计可见 |
| 长会话压缩 | Claude Code 自带自动压缩;阈值可在设置里用 `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` 调整 |
| MCP 工具按需加载 | 已有 `ENABLE_TOOL_SEARCH`(设置 → 高级):MCP 很多时能显著缩小基础前缀 |

## 给用户的建议

- 在**一个会话里问很多不相关的问题**时:历史越长,每轮「读缓存」越多,也更容易触发压缩。无关的新话题建议**新开对话**(或 `/compact`)。
- 间隔超过 5 分钟再继续,会有一次「缓存重写」,属正常现象。
- 想看真实账单维度:用「上下文用量」面板与「提示缓存」统计,分别看 **新输入 / 缓存写入 / 缓存读取**,不要把三者加起来当成全价 token。
