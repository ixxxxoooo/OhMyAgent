> @author ixxxxoooo · 2026-10-21

## 0. 背景与目标

- **现状**:OhMyAgent 只有一个 Agent 工作台窗口(`OhMyAgentApp.swift:199`,`Window(id: "main")`,全局单例 `AppEnvironment.shared.workbench`,共 68 处引用)。IDE 的大部分零件已经有了,但没有拼成 IDE:
  - 编辑器分组/标签/拆分:`DockLayout` 等
  - TextKit 2 编辑器:`EditorKit`
  - LSP:`LSPKit`
  - Git 面板:`SCMView`
  - SwiftTerm 终端
  - 窗口化文件树:`ExplorerFlatten`
  - 三元组搜索索引:`SearchIndex`
  - 中央搜索:⌘K `HubSearch`
- **参照**:~/BaoCode 其实是 Flutter 写的,原生 Swift 只占约 2.7K 行宿主代码。可以借鉴的是它的交互模型:
  - 「Open in IDE / Back to Chat」两个按钮在标题栏同一位置互换,宽度一致,切换时不跳动;
  - `window.ideWindows`:IDE 按文件夹各开一个窗口,同一文件夹已开就复用;
  - 窗口列表持久化到 `windows.json`,启动时恢复;
  - 切换快捷键 ⌃⌘I。
  它的问题我们要避开:没有性能预算、只有一个编辑器组、内存没有度量。
- **目标**:用 Swift 6 + AppKit/SwiftUI 实现 Cursor 风格的 IDE 窗口(布局对照截图),要求:
  - 可以同时开多个 IDE 窗口;
  - 与 Agent 窗口互相一键切换;
  - 项目、会话、文档缓冲、主题全部共享;
  - 主题实时跟随;
  - 有严格的性能与内存预算,并接入现有的基准、浸泡和 CI 体系。
- **已确认的决策**:
  1. **窗口模型**:独立窗口、共享状态。Agent 窗口全局只有一个,IDE 窗口按工作区可开多个,每个 IDE 窗口右侧自带 Agent 面板。
  2. **语法引擎**:tree-sitter。
  3. **功能范围**:核心编辑 + LSP 全功能;源代码管理 + 全局搜索替换。
  4. **不做**:DAP 调试、tasks/launch 运行配置、VS Code 扩展宿主。

## 1. 总体架构

```
┌──────────── 共享层(进程内唯一)──────────────────────────────────┐
│ WorkbenchModel(项目/会话/conversations) ThemeRuntime  LSPManager │
│ DocumentStore(新,按 URL 共享文本缓冲) SearchIndexRegistry GitStore│
│ TerminalStore  SyntaxService(新,tree-sitter 解析 actor)          │
└──────────────────────────────────────────────────────────────────┘
        ▲                          ▲                    ▲
 Agent 窗口 (现有 main)     IDE 窗口 #1            IDE 窗口 #2 …
 右上角「编辑器 ↗」         IDEWindowController + IDEWindowModel(每窗一份)
                             右上角「Agents Window ↗」
```

### 1.1 新模块

| 模块 | 职责(都不含视图,除非另注) |
|---|---|
| `IDEKit` | 每个窗口的数据:<br>· `IDEWindowModel`:工作区根、编辑器 `DockLayout`、底部面板 `DockLayout`、侧栏视图、Agent 面板状态、各区尺寸<br>· `IDEWindowRegistry`:多窗口、最近使用顺序、「同一根目录复用窗口」规则;持久化到 `AppEnv.supportDirectory/ide-windows.json`<br>· `IDECommandRegistry`:命令 id、when 条件、快捷键<br>· `ProblemsStore`:全工作区诊断聚合<br>· `IDEStatusModel` |
| `SyntaxKit` | tree-sitter 封装:<br>· 增量解析 actor `SyntaxService`<br>· 高亮 query → `SyntaxKind`<br>· 折叠区间、括号配对、缩进、作用域(给粘性滚动/大纲兜底用)<br>· 不支持的语言回退到现有 `SimpleLexer` |
| `Vendor/TreeSitterGrammars` | C target。由 `Scripts/vendor-grammars.sh` 拉取指定 tag 的 `parser.c/scanner.c` 和 `highlights.scm`(版本锁定,已提交入库)。<br>首批语言:Swift、TS/JS/TSX、Python、Go、Rust、C/C++、JSON、YAML、TOML、Markdown、HTML、CSS、Bash |

依赖:`tree-sitter` 核心与 `SwiftTreeSitter` 用 `exact:` 锁版本。包体积增量预算 ≤ 8MB。

### 1.2 AppKit / SwiftUI 分工

原则:热路径用 AppKit,外壳用 SwiftUI。

| 区域 | 技术 | 说明 |
|---|---|---|
| 编辑器正文、行号栏、minimap、粘性滚动、多光标层 | **AppKit** | 在 `CodeEditorView`/`EditorTextView` 上扩展;光标闪烁用 CALayer 动画,不用 Timer |
| 资源管理器 | **AppKit** `NSTableView`,固定行高 | 复用 `ExplorerFlatten`、`ExplorerTree`、`ExplorerActions`、`ExplorerUndo`、`GitDecorationIndex` 等数据层 |
| 搜索结果、问题列表、引用列表 | **AppKit** `NSOutlineView` | 结果可能上万条 |
| 终端 | **AppKit** SwiftTerm | 复用 `TerminalController`/`TerminalStore` |
| 窗口与标题栏 | **AppKit** `NSWindowController` | 不用 SwiftUI `WindowGroup`,以便精确控制生命周期、释放与恢复 |
| 活动栏、状态栏、面板外框、标签条、SCM、Agent 面板、设置 | SwiftUI | 复用 `TabBarView`、`SCMView`、`ChatView`、`ComposerView` |

## 2. 切换与多窗口规则

1. **Agent → IDE**
   - Agent 窗口右上角「编辑器 ↗」或 ⌃⌘I:若当前项目已有 IDE 窗口就聚焦它,没有就新建。
   - 同时带过去:当前会话(在 IDE 的 Agent 面板里选中)和当前打开的文件。
   - ⌥ 点击:强制新开窗口。
2. **IDE → Agent**:「Agents Window ↗」或 ⌃⌘I:聚焦 Agent 窗口,并选中 IDE 面板里当前的会话。
3. **两个按钮的尺寸规则**:由同一个 `TitlebarMetrics.modeSwitchWidth` 计算,标题栏右侧簇不跳动。同步更新 `rightClusterWidth`。
4. **多 IDE 窗口的入口**:
   - 文件菜单「新建 IDE 窗口」⇧⌘N、「在新 IDE 窗口打开文件夹…」;
   - 项目栏右键「在 IDE 中打开」。
5. **恢复与关闭**:启动时按 `ide-windows.json` 恢复;关窗前有未保存文件时用 `OMDialog.confirm` 询问。
6. **命令路由**:引入窗口上下文 `WindowContext`(以环境值 + `NSApp.keyWindow` 判定),`AppActions` 与菜单命令按键盘窗口分派。逐步改造 68 处 `AppEnvironment.shared.workbench` 中与「当前窗口」有关的调用(如 `focusedHost`、`closeActiveTabOrWindow`)。
7. **文档共享**:新建 `DocumentStore`,在现有 `FileDocuments.swift` 基础上扩展。同一 URL 无论在哪个窗口、哪个标签打开,都共享同一个 `NSTextContentStorage`,保证编辑一致、撤销栈一致,且只占一份内存。

## 3. 主题适配

- IDE 全部取色走 `OMColors` / `ThemePalette`:
  - 活动栏与侧栏:`sidebar`;
  - 编辑器:`editorBackground`;
  - 面板:`surface`;
  - 选中:`selectedFill`;
  - 强调:`accent`。
- AppKit 部分监听 `ThemeRuntime.didChange`,模式与 `CodeEditorView.themeDidChange` 相同。
- tree-sitter 的 capture 要扩展映射到更细的语法种类:variable、operator、punctuation、constant、attribute、tag。在 `ThemePalette` 里新增**可选**颜色;缺省时从现有 7 个语法色推导,存量主题不用改。`ThemeTokenTests` 增加对比度守卫。
- minimap 按主题 id 和语法色缓存位图,主题切换时整张失效重画。
- 每个界面都要分别在纸感(`allowsGlass == false`)和玻璃主题下验证。`OMA_THEME` 截图对比 `paper-light`、`paper-dark`、`cursor-light`。

## 4. 性能与内存预算(IDE 专项,写入预算文档并接入基准)

测量条件:release 构建;`DemoPerfProjects` 的 1 万文件项目;50k 行 / 1.6MB 大文件。

| 类别 | 指标 | 预算 |
|---|---|---|
| 切换 | Agent ⇄ IDE(窗口已存在)首帧 | ≤ 50ms |
| 切换 | 新 IDE 窗口冷开到可交互 | ≤ 250ms(恢复树和 5 个标签时 ≤ 400ms) |
| 打开 | 普通文件(≤1MB)到首个高亮帧 | ≤ 50ms |
| 打开 | 50k 行文件,不换行 | ≤ 150ms(现基线 800ms) |
| 打开 | 50k 行 tree-sitter 全量解析(后台) | ≤ 300ms |
| 输入 | 按键到上屏 P95 / max(50k 行,换行与不换行都测) | ≤ 8ms / ≤ 16ms(现不换行基线 115ms) |
| 输入 | tree-sitter 增量重解析(后台) / 主线程应用高亮 | ≤ 5ms / ≤ 2ms |
| 滚动 | 平均帧间隔 | 120Hz 下 ≤ 8.6ms;60Hz 下 ≤ 16.7ms |
| 滚动 | 掉帧(>33ms) | 0 次 / 10 秒扫描 |
| 渲染 | minimap 编辑后局部重画 | ≤ 2ms |
| 资源管理器 | 1 万文件全部展开 | ≤ 50ms |
| 资源管理器 | 滚动单帧 | ≤ 8ms |
| 搜索 | 全文搜索首批结果 / 完成 | ≤ 100ms / ≤ 1s |
| 搜索 | ⌘P 每次按键(1 万文件) | ≤ 16ms |
| 标签 | 切换(热 / 冷) | ≤ 16ms / ≤ 50ms |
| 主题 | 所有窗口切换主题 | ≤ 100ms |
| 内存 | 空 IDE 窗口增量 | ≤ 35MB |
| 内存 | 再打开 10 个普通文件 | 增量 ≤ 60MB |
| 内存 | 打开 50k 行文件 | ≤ 80MB(现基线 209/740MB) |
| 内存 | 3 个 IDE 窗口空闲时应用自身占用(不含子进程) | ≤ 250MB |
| 内存 | 开关 IDE 窗口 20 次后漂移 | ≤ 10MB |
| CPU | 空闲且 IDE 窗口在前台 | ≤ 1%(无轮询,Git 轮询退避) |
| 卡顿 | 基准过程中主线程 >50ms 的卡顿 | 0 次 |

**度量落地**:

- **基准目录**:`DemoBenchmarkCatalog` 新增 `ide` 分类(先登记为 info,实现后再挂预算)。
- **运行入口**:
  - `Scripts/demo-bench.sh --only ide`;
  - 新钩子 `OMA_IDE_SWEEP=open,typing,scroll,minimap,switch,explorer,search,theme|all`,结果写 perf 日志「IDE 基准」;
  - `Scripts/perf-ui.sh` 增加 `ide` 模式。
- **按键延迟**:keyDown 打 signpost,用 `NSView.displayLink` 回调取下一次上屏时间戳,算差值。
- **容量计量**:`GaugeRegistry` 增加 `ide.windows`、`ide.documents`、`ide.syntaxTrees`、`ide.minimapBytes`、`ide.keptAliveTabs`。
- **浸泡**:`perf-soak.sh` 增加 3 个 IDE 窗口加编辑脚本的场景;开关窗口泄漏测试。
- **回归门禁**:`perf-report.py` 实现原计划里「相对基线退化 >15% 即失败」(当前缺失),基线放 `Scripts/perf-baseline.json`。
- **自查浮层**:开发版状态栏可开 Perf HUD(FPS、最近一次按键延迟、footprint)。
- **内存策略**:
  - 窗口隐藏或最小化时:降低 `TabKeepAlive` 上限,释放 minimap 位图、高亮缓存和不可见标签的语法树;
  - 内存告警时复用现有的 `DispatchSource` 压力回调;
  - LSP 按根目录跨窗口共享(`LSPManager` 已按 root 复用),空闲 180 秒回收。

## 6. 主要风险与对策

1. **TextKit 2 不换行模式与大文件性能**:I1 设决策关卡,方案 B 是自研 CoreText 编辑器,接口(`CodeEditorView` 的公开 API)保持不变。
2. **TextKit 2 折叠不好做**:I7 先做最小验证;不行就用「隐藏段落的内容存储代理」方案,或在方案 B 里原生支持。
3. **多光标与输入法**:组字(marked text)期间只作用于主光标,组字结束后再同步到其他光标。
4. **全局单例假设多窗口不存在**:I2 先做 `WindowContext` 路由,逐处改造调用点并补测试,避免命令打到错误的窗口。
5. **tree-sitter 体积与许可**:语法库只拉 MIT 许可的固定 tag;记录到第三方声明里。
6. **多窗口内存叠加**:语法树、minimap、高亮缓存按窗口可见性回收;LSP 与搜索索引按根目录共享。

## 7. 规范遵守清单

- Swift 6 严格并发,零警告;每个新增文件写 `@author`,每个类型与方法写中文文档注释。
- 只用 `OMFonts`、`OMColors`、`OMRadius`、`Image.om`,以及 `OMPickList`、`omContextMenu`、`OMDialog`、`omTooltip`。
- 新增文案同步到 `en.lproj`。
- 新增落盘路径一律经 `AppEnv.supportDirectory`。
- 日志只用 `Log.*`,带 windowId / documentId 和耗时。
- 新功能必须带 Swift Testing 测试:
  - `IDEKitTests`:注册表、持久化、when 条件、`ProblemsStore`;
  - `SyntaxKitTests`:增量解析一致性、高亮映射;
  - `EditorKitTests`:多光标、增量 `LineIndex`、折叠区间;
  - `LSPKitTests`:假服务器。
- 新增调试钩子:`OMA_IDE=1`(启动时直接开 IDE 窗口)、`OMA_IDE_ROOT`、`OMA_IDE_OPEN_FILE`、`OMA_IDE_SWEEP`,并登记到 AGENTS.md 第 6 节。
