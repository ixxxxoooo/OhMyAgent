# 会话本地存档与即时回显

> @author ixxxxoooo

## 背景
- 打开历史会话原来一律走 `session/load`,必须等引擎:Claude 适配器先拉起 `claude` 进程(1.3–2.1 秒)再回放;其他引擎每次向引擎拉全量,引擎不在或会话被引擎清理就看不了。
- 侧栏**列表**早已缓存(`CachedSession`),**内容**没有客户端存档。
- 目标:所有会话打开时先从本地秒开;本地没有的拉取一次后落盘;引擎侧有新内容时后台校验替换。

## 参照 Claude Code 自身的转录实现
`~/.claude/projects/<cwd 变形>/<sessionId>.jsonl`(本仓库 `ClaudeAgentKit/Session/TranscriptStore.swift` 读取同一格式):
1. 一会话一文件、追加写、从不改写;每行一条完整记录(消息写完才落一条)。
2. 元数据(标题等)也是追加记录、后写者胜。
3. 列表不建数据库:扫目录 + 头尾轻量读取。
4. 读取容错:坏行/截断末行跳过。
5. 有保留期(`cleanupPeriodDays`,默认 30 天):这也是需要自有存档的理由。

## 方案
### 第 0 步:Claude 回放先于拉起进程
`ClaudeAcpAgent.loadSession`:读转录 → 先回放发出更新 → 再 `getOrCreate`。实测回放约 15ms,进程启动约 0.5–0.7 秒,历史不再等进程。

### 存档格式(`SessionArchiveFormat`)
- 路径:`AppEnv.supportDirectory/session-archive/<agentId>/<会话 ID>.jsonl`,0600;非字母数字的 ID 取 SHA256(防穿越、防过长)。演示模式随主目录重定向进沙盒。
- 行:`{"t":"h",schema,agentId,sessionId,cwd,createdAt}` 头;`{"t":"u","u":<原始 session/update>}` 正文;`{"t":"m","syncedAt"}` 元数据(后写者胜)。
- 消息粒度:同一消息的文本片段在内存合并,消息切换或回合结束才写一行;`available_commands`/`config_options` 不落盘;只有元数据的空会话不建档。
- 格式版本不符视为不存在(派生数据,重新拉取即可)。

### 写入(`SessionArchive` actor + `SessionArchive+Writer`)
- 所有命令经单一 `AsyncStream` 有序执行,落盘顺序与事件到达顺序一致;缓冲 64KB 或 2 秒后写盘,回合结束立即写盘并写 `syncedAt`。
- 原始载荷来自 `ACPClient.setUpdateTap`(解析前回调)。**不用 `Mutex` 保存闭包**:测试中复现盒子析构时栈溢出,改为 `NSLock`。
- 用户消息由客户端补记(引擎不回显用户自己发的消息),只记文本与图片。
- 全量同步:`beginSync` 写 `.sync` 临时文件,`endSync` 时与现档比较,内容相同只追加 `syncedAt`,不同才 `replaceItemAt` 原子替换;失败丢弃临时文件、旧档不动。结束同步前先过事件屏障,保证回放事件都已交给存档。

### 读取(`SessionModel+ArchiveOpen`)
1. 新标签恢复(`prepareRestore`):不等连接,立即回显存档;连接就绪后 `openSession(force:)` 只接回引擎、不重置时间线。
2. 同一标签切换(`openSession`):有存档则回显后接回;否则走原引擎回放(`loadFromEngine`),回放即全量同步。
3. 接回策略:存档未落后且引擎支持 `resume` → 只 `session/resume`;落后(引擎 `updatedAt` > `syncedAt` + 5 秒)或只能 `load` → **静默同步**:回放事件不进时间线(模式/配置/命令/用量照常应用),只写临时文件,内容变化才从存档重渲染。
4. 接回期间的发送进入排队;引擎找不到会话时保留存档内容并提示,不当作空会话隐藏。
5. 回显按 200 条一批喂时间线,批间让出主线程。

### 删除与管理
- 删除会话:`SessionArchive.purge(sessionId:)` 删除各引擎下的存档,并忽略之后到达的更新。
- 设置 → 通用 → 会话存档:占用统计、一键清空(默认永久保留)。
- 会话右键「从 Agent 重新同步」:静默同步当前会话。

## 验证
- 单元测试 `SessionArchiveTests`(13 项):合并、空会话、容错、版本、同步四种结果、文件名、陈旧判定、删除/清空/跨引擎清除、延迟写盘。
- 接线测试 `SessionArchiveFlowTests`(脚本化 Agent,5 项):实时回合落盘、回放建档、存档命中不经引擎回放且可继续对话、存档落后时静默同步替换且内容不重复、手动重新同步。
- 真实应用(开发版,Claude):引擎回放建档 `outcome=created`;重启后同一会话「会话存档已回显 ms=23」,早于「Agent 已就绪」约 0.7 秒。
