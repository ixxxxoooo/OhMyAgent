## 1. 产品与架构一页纸

**定位**:macOS 27 专用、100% 原生(Swift 6 + SwiftUI + AppKit,唯一例外:内置浏览器标签页用 `WKWebView`)的 Cursor 风格 Agent 工作台,另带一个原生 IDE 窗口。通过 ACP(stdio JSON-RPC)接管本机已安装的 Claude Code(另支持 OpenCode、Antigravity 等 ACP 引擎)。**不做账号登录 UI**,直接使用本机 `claude` 的凭据。

**两个窗口形态**
| 窗口 | 技术 | 说明 |
| --- | --- | --- |
| Agent 窗口(主窗口) | SwiftUI `Window` 场景(id `main`) | 无标题栏;左项目栏 / 中栏(会话与标签页)/ 右栏 Dock 三区;设置页并入此窗口整页显示(⌘,) |
| IDE 窗口 | AppKit `NSWindow`(每工作区可多开) | 标题栏命令中心 / 活动栏 / 侧栏 / 编辑器组 / 底部面板 / Agent 面板 / 状态栏;⌃⌘I 与 Agent 窗口互切;可开「融合模式」共用会话 |

**分层(重构时的边界)**
```
┌ 视图层  OhMyAgentApp(SwiftUI/AppKit)+ DesignSystem + IconKit        ← 本次重构的主要对象
├ 模型层  ChatKit(SessionModel/TimelineStore…)、WorkbenchKit(WorkbenchModel/DockLayout…)、IDEKit、EditorCore   ← 无视图,建议保留
├ 能力层  GitKit / LSPKit / DiffKit / ClaudeConfigKit / AutomationKit / CanvasKit / SpreadsheetKit / MermaidKit
└ 引擎层  ACPKit → ClaudeAgentKit(原生适配器)/ AgentHost(进程、Bridge MCP)/ ProviderProxyKit(本机网关与协议转换)
```
- 引擎层与模型层对 UI 暴露的状态/动作清单见 **文档 09**——这是「替换视图而不动引擎」的契约。
- 代码规模(行):`OhMyAgentApp` 约 4.9 万、`ChatKit` 1.65 万、`EditorKit` 1.3 万、`ClaudeAgentKit` 0.7 万、`WorkbenchKit` 0.64 万、`ACPKit` 0.6 万,总计约 12 万行 Swift;约 1400 个测试。

## 5. 设计不变量

重构视觉与布局时,以下约定来自现有规范与代码守卫,建议作为新系统的**硬约束**(或有意识地修改并同步守卫):

1. **令牌单一来源**:颜色只来自 `OMColors/ThemePalette`;字号只来自 `OMFonts`(随「界面字号」缩放);圆角 `OMRadius`(tag/control/card/floating/modal);间距 `OMSpacing`(4 的倍数);动效 `OMMotion.standard`(150ms)。禁止写死色值、系统色、纯黑白。(01)
2. **主题全渗透且热更新**:读取令牌即自动随主题刷新,不用 `.id()` 强制重建;AppKit 桥接监听 `ThemeRuntime.didChange`。(01)
3. **纸感规则对所有主题生效**:字重 ≤ medium、系统字体无衬线、三档阴影、Ember 仅作文字/强调、主按钮用 Ink/加深强调色、不透明卡片 + 发丝线(玻璃主题除外)、禁止装饰性渐变与发光。(01)
4. **侧栏 ≠ 内容区背景**:每个主题必须同时提供 `surface` 与 `sidebarBackground`;`#EFEFEF/#F6F6F7` 仅属于「跟随系统」与「Cursor 浅色」。设置页左栏宽 = 工作台左栏宽。(01、07a)
5. **组件统一**:按钮 `OMButtonStyle`(primary/secondary/plain/destructive/icon,默认 24pt)、下拉选择 `OMPickList`(无箭头浮层、搜索、↑↓/回车/Esc)、右键菜单 `omContextMenu`、对话框 `OMDialog/OMModal`(禁 `NSAlert`)、提示 `omTooltip`(禁 `.help`)、复制 `OMCopyButton`、档位 `OMStepSlider`、图标 `Image.om`(Lucide,禁 SF Symbol)、文件图标 `OMFileIcon`。(01)
6. **只读文本叶子**:代码块/命令输出/Diff/表格/Markdown 文字统一为 AppKit 只读文本视图,跨叶子选择由 `SelectionHub` 接管;复制取模型文本。重做时若改用 SwiftUI 原生文本,会丢失跨块连续选择。(03)
7. **窗口化渲染**:项目栏固定行高窗口化、时间线只挂载最近 40 轮、资源管理器扁平化窗口、子代理标签最近 120 单元。这些是性能底线(见 08 性能预算)。(02、03、05)
8. **标签保活 LRU**(预算 5)、隐藏标签退出焦点链并暂停轮询。(02)
9. **无障碍**:仅图标控件必须有 tooltip + accessibilityLabel;动画经 `omWithAnimation` 遵循「减弱动态效果」。(01)
10. **本地化**:中文字面量为键,新增文案同步 `en.lproj`(约 2978 键);`zh-Hans` 自动生成。(08b)
11. **稳定版/开发版隔离**:所有落盘路径经 `AppEnv.supportDirectory`。(08)
12. **日志只用 OMLog**,严禁记录密钥;`catch` 必须记日志。(08)

## 6. 重构建议:分层、顺序与风险

> 以下为**建议**(非源码事实),依据各文档「重构注意事项」归纳。

### 6.1 建议的分层策略
- **保留不动**:引擎层与模型层(文档 09 的 UI 契约)。视图重写只通过 `SessionModel`、`WorkbenchModel`、`IDEWindowModel`、`ThemeRuntime` 等公开接口取数与发动作,可避免触碰 ACP 协议与适配器。
- **优先重写/重做**:`DesignSystem`(令牌与组件)→ 外壳布局(02)→ 会话流(03)→ 输入区(04)→ 标签页(05)→ 设置页(07)→ IDE(06)。理由:下层令牌与组件被所有上层复用,先稳定再迁移。
- **布局持久化要保持兼容**(或写迁移):`workbench.json`(02b)无顶层 version,靠 `sanitize()` 与 Legacy 迁移容错;`ide-windows.json`、`providers.json`、`agents.json`、UserDefaults 键(08b)都有用户数据。

### 6.2 风险与踩坑(来自开发记录,详见各文档「重构注意事项」)
- **性能底线**:SwiftUI 整窗单一视图图的每帧事务开销是已知瓶颈;项目栏尝试独立 `NSHostingView` 渲染岛无收益;`LazyVStack` 时间线要配窗口化;`TimelineWindow` 之外的叶子不参与 ⌘A。
- **AppKit 桥接陷阱**:`updateNSView` 内直接改 `@State` 会被丢弃;自绘视图里 `NSRectFill` 会让整个窗口内容区空白;`NavigationSplitView`/空 unified 工具栏会吞顶部点击(因此用 `hiddenTitleBar` + 自绘分栏);`.toolbar(.hidden)` 会连红绿灯一起隐藏;`MenuBarExtra(isInserted:)` 传读写 Binding 会 100% CPU。
- **选择与复制**:单击用户消息即进入编辑(拖选可复制);`copyTransform` 必须保持长度不变。
- **终端**:SwiftTerm 1.11.2;`OMTerminalView` 忽略 <16pt 退化尺寸以避免回滚缓冲区全量重排;关窗要释放缓冲(循环引用泄漏)。
- **编辑器**:单行 >4000 列硬断保护;`syntaxPending` 首批着色前不画无色正文;`EditorSwapGate` 防切换闪屏。
- **测试教训**:只测纯函数、没测视图接线会漏回归(K83);UI 测试用轮询而非固定睡眠。
- **验证约定**:`Scripts/restart.sh` 重启开发版;自绘菜单/对话框用键盘验证,不依赖合成点击;演示模式 `Scripts/demo.sh` 是测试会话流/工具卡的首选。

### 6.3 建议的验收方式
- 以文档为清单逐条建立验收用例(每个功能点已写明入口/状态变体/边界)。

## 8. 术语表

| 术语 | 含义 |
| --- | --- |
| ACP | Agent Client Protocol(stdio JSON-RPC),本应用与各 Agent 引擎的协议 |
| Bridge | 进程内 HTTP MCP 服务(挂在 `LocalGateway`),给 Agent 提供 `open_file/show_diff/canvas_*/browser_*/search_code` 等工具 |
| LocalGateway | 本机回环网关,一个监听同时承载模型代理与 Bridge,路由令牌在 URL 路径里 |
| 模型映射 | Claude Code 的槽位别名(`oma-*`)→ 任意提供商模型 |
| Dock | 标签停靠布局(`DockLayout`:分屏树 + 标签组),中栏与右栏各一个 |
| 预览标签 | 单击打开、可被下一个预览替换的标签(斜体标题) |
| 纸感 | 默认主题「Cursor 纸感」:暖纸色、不透明卡片 + 发丝线、无玻璃 |
| 玻璃主题 | `allowsGlass == true`,卡片与浮层使用 Liquid Glass |
| 融合模式 | 设置 → 通用;开启后 Agent/IDE 窗口原地互切并共用同一 `SessionModel` |
| 叶子(Leaf) | AppKit 只读文本视图单元(代码块/输出/Diff/表格/Markdown 文字段) |
| SelectionHub | 跨叶子连续选择与复制的中枢 |
| 任务坞 | 输入框上方的排队/子代理/后台命令胶囊与面板 |
| Hub | ⌘K 中央搜索窗(`HubSearch`) |
| 休眠/唤醒 | 闲置会话释放 Agent 进程(闲置 10 分钟/上限 3),再次使用时重连 |
| 演示模式 | 隔离沙盒 + 脚本化 Agent(`OMA_DEMO=1`),用于无真实模型的 UI 验证 |
